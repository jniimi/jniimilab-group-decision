# ゼミ 2・3年生 研究グループ マッチングシステム

Streamlitで作った、研究室ゼミ向けの**グループ意思決定支援ツール**です。

3年生（5グループ）と2年生（人数は `data/students.json` の登録数）が相互に希望を出し合い、簡易スコアリング＋グリーディー割り当てで研究グループに振り分けます。

## 主な特徴

- **共通アクセスキー**で入室（シンプルな認証）
- **2年生**: 5グループの完全ランキング投票（1位〜5位）
- **3年生グループ**: 欲しい2年生を上位N人まで順位付きで投票（Nは管理者調整可）
- **管理者機能**:
  - 重み調整（学生希望 vs グループ希望）
  - Nの変更
  - 名前リストの直接編集
  - マッチング一発実行 + 結果CSV出力
  - 投票進捗確認（管理者限定）
- 投票途中経過・人気情報は**管理者画面のみ**で見える設計（学生・3年生には非公開）

## 使い方（uv 推奨）

このプロジェクトは **uv**（高速な Python パッケージマネージャー）で管理しています。

### uv を使った場合（推奨）

```bash
# 1. 依存関係のインストール（初回のみ）
uv sync

# 2. アプリの起動
uv run streamlit run streamlit_app.py
```

ブラウザで `http://localhost:8501` が開きます。

### pip を使いたい場合（後方互換）

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```

> **注意**: 将来的には `uv` がメインになります。`requirements.txt` は互換性のために残していますが、uv での管理を強く推奨します。

## 初期設定

- **一般ユーザー用キー**: `jniimi2026`
- **管理者用キー**: `admin-jniimi2026`
- 両方のキーは `data/config.json` で変更可能です（管理者画面からも変更可）
- サンプルデータ: グループA〜E + 学生01〜15（`data/students.json` を編集すれば人数を自由に変更可能。すべて管理者画面からも編集可）
- デフォルト:
  - 3年生投票上限 N = 3人
  - 学生希望重み 60% / グループ希望 40%

### 重要な運用ルール

- 管理者用キーで入室すると、**自動的に管理者画面のみ**が表示されます。
- 一般ユーザー用キーで入室した人には、管理者画面の選択肢自体が一切表示されません。
- 学生や3年生グループの投票画面では、投票進捗（何人投票したか）のみが見え、人気状況などは一切公開されません。

## データの永続化

`data/` フォルダ内のJSONファイルにすべて保存されます。

- `config.json` — アクセスキー・重み・N
- `groups.json` / `students.json` — 名前リスト
- `votes.json` — 投票データ

Git管理する場合、投票データは `.gitignore` に追加することをおすすめします（任意）。

## マッチング方式（v1）

1. 学生のランキングを 5〜1 点に変換
2. 3年生グループの希望を N〜1 点に変換
3. 重み付き合計スコアを計算
4. 最高スコアのペアから順にグリーディー割り当て（最大4人/グループ）
5. 2人未満のグループが出たら、スコア低下が最小になるよう再バランス
